A production-grade Flutter mobile application that displays open Pull Requests from GitHub public repositories. Built with **very_good_cli (VGV) architecture**, following clean code principles and Flutter best practices.

---

## ✨ Features

### Core Features
- **Simulated Authentication**: Login with fake token storage using `flutter_secure_storage`
- **GitHub API Integration**: Fetch open pull requests from any public repository
- **Pull-to-Refresh**: Refresh PR list with swipe gesture
- **Reactive State Management**: Using `flutter_bloc` for predictable state management
- **Dark Mode Support**: Automatic theme switching based on system preferences
- **Error Handling**: Comprehensive error states with retry functionality
- **Empty States**: User-friendly empty state when no PRs exist

### Pull Request Display
Each PR card shows:
- **Title**: Pull request title (max 2 lines)
- **Number**: PR number with # prefix
- **Description**: First 3 lines of PR body (if available)
- **Author**: Username with avatar image
- **Created Date**: Relative time formatting (e.g., "2 days ago")

## 🏗️ Architecture

This project follows **very_good_cli (VGV)** architecture principles with feature-first structure:

```
lib/
├── app/                      # Root application layer
├── bootstrap.dart            # App initialization & BlocObserver
└── features/
    ├── auth/                 # Authentication feature
    │   ├── bloc/            # AuthBloc for state management
    │   ├── repository/      # Token storage logic
    │   ├── view/            # Login UI
    │   └── auth.dart        # Barrel file
    └── pull_requests/       # Pull requests feature
        ├── bloc/            # PullRequestsBloc
        ├── models/          # Data models
        ├── repository/      # GitHub API calls
        ├── view/            # PR list UI
        └── pull_requests.dart
```

### State Management
- **AuthBloc**: Manages authentication (login/logout/token check)
- **PullRequestsBloc**: Manages PR fetching and refresh

## 🔐 Authentication & Token Handling

### Flow
1. **App Launch** → Check if token exists
2. **No Token** → Show Login Screen
3. **Login** → Store fake token (`abc123`) using `flutter_secure_storage`
4. **Authenticated** → Navigate to PR List
5. **Logout** → Clear token and return to login

### Security
- Uses `flutter_secure_storage` for encrypted token storage
- Platform-specific secure storage (Keychain on iOS, EncryptedSharedPreferences on Android)
- Token persists across app restarts

## 🎯 Demo Instructions

### Quick Start Flow

1. **Launch App** → Brief loading screen
2. **Login Screen**:
   - Read demo mode information
   - Tap "Login" button
   - Wait 1 second (simulated delay)
3. **Repository Input**:
   - Default: `flutter/flutter` (pre-filled)
   - Or try quick preset chips
   - Tap "Fetch PRs"
4. **PR List**:
   - View all open PRs
   - Pull down to refresh
   - Tap PR for details (snackbar)
   - Tap edit icon to change repository
   - Tap logout to return to login

## 📝 Known Limitations

1. **No Real Authentication**: Uses simulated token
2. **No Pagination**: Fetches default 30 PRs from API
3. **No PR Details Page**: Shows snackbar on tap
4. **No Offline Support**: Requires network
5. **Rate Limiting**: 60 requests/hour for unauthenticated API calls
